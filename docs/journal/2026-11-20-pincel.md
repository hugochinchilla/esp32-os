# Pincel, the drawing program

Backlog item 86. Branch `claude/project-thread-t1ukje`.
[Decision](../decisions/pincel.md).

## What was asked

The owner, 2026-11-20:

> inicia una tarea para crear una app de paint básica, como el paint de windows 95

The coordinator's note with it: pencil, brush, eraser, line, rectangle,
ellipse, fill, a colour palette, and open and save of pictures in C:; an
original design that fits this system, not a copy of any product; a
program file in `C:\Programs` like those of item 82, the same on the
board, in the Linux program and in the web page.

## What was found

- Since item 82 a program is a folder in `programs/`: its sources, its
  pictures in `art.hpp`, `APP_INFO` and `APP_MAIN`. The builds pick the
  folder up by themselves (the PC's tests link it in, the Linux program
  and the board get a file, `tools/flash.py` copies it), and the Start
  menu lists what is in `C:\Programs`. Nothing else has to name a new
  program.
- A program paints rectangles of its window called pictures
  (`os::ui::picture`) and is told of the left button in them from Down to
  Up, with the moves between. It is not told of the pointer moving with no
  button held, and of the right button only that it went down.
- `gfx::Bitmap` is a width, a height and one board colour a pixel, and a
  canvas draws the part of one that is in view. A sheet kept that way is
  painted with one call.
- The system decodes BMP, PNG, JPEG and GIF row by row
  (`image::Decoder`) and turns the rows into board colours
  (`image::Converter`). There is nothing that writes a picture file.
- The Editor is the model for a program with a document: many copies,
  `set_document`, "Do you want to save the changes?", the file dialogs,
  and a save done by a background job with the window locked.

## The options considered, and what was chosen

Put to the owner as one message with what the agent would do, and one card
for the name. He chose **Pincel** (the others were Cochinilla, Colibrí and
Painter). The rest he has not answered yet; it is recorded as to confirm.

- **The file it saves.** BMP of 8 bits a pixel with the board's 256
  colours as its palette: 1,078 bytes of header and the rows as they are.
  The decoder reads it back to the very same bytes. PNG and GIF would be
  smaller files but need a compressor (deflate, LZW) the system does not
  have, and a sheet of 320 by 240 is 78 KB on a drive of 9 MB. Chosen: BMP.
- **Undo.** A second copy of the sheet, taken when the button goes down:
  one level, and Undo again brings the change back, because the two only
  change places. Several levels would cost a copy each (480 KB at 800 by
  600); keeping only what a stroke changed is more code. Chosen: one copy.
  The same copy serves two more things: a line or a shape being pulled is
  drawn over the sheet "as it was", and the fill uses it (below).
- **Opening.** At once, under the hourglass, as the Editor loads a text.
  The Picture viewer decodes from a timer so that a photograph appears as
  it comes; a drawing program has no use for half a picture. Chosen: at
  once. How long a large JPEG takes on the board is not known.
- **Where the tools' code lives.** In a file of its own, `sheet.cpp`,
  which knows nothing of windows: the tests draw on a sheet of their own.

## What was built

- `programs/pincel/sheet.hpp`, `sheet.cpp`: the tip (round or square), a
  line, a rectangle, an ellipse, the fill, flips, inverting, and the BMP
  header.
  - An ellipse is worked out row by row with whole numbers: a pixel is
    inside when its middle is. Its outline is every pixel that is not
    inside the ellipse of the box drawn in by the edge's thickness, and at
    least every pixel with the outside above or below it, so that a thin
    outline has no gaps.
  - The fill goes by runs of a row and keeps the places still to look at
    in a list. When the list is full it drops them, and afterwards looks
    the sheet over for places that touch what it filled, which it can tell
    from the Undo copy (there the target colour, here the new one). So any
    amount of working memory is enough; it asks for 32 KB while it runs.
- `programs/pincel/pincel.cpp`: the window (seven controls: tools,
  options, sheet, two scroll bars, palette, status line), the menus File,
  Edit and Image, the Size dialog, the settings file with the palette.
  Ctrl+Z, Ctrl+S, Ctrl+O and Ctrl+N.
- `programs/pincel/art.hpp`: its icon at 16 and 32 dots and the eight
  tools' pictures, drawn for it. The tools are one colour, the theme's
  ink.
- `host/tests/test_pincel.cpp` (the PC tests `pincel` and
  `pincel_pictures`), and ten reference pictures, `90-pincel-new` to
  `97-pincel-theme-*`.

## How it was tested

On the PC only. Compiled for the board: see the pull request. Not run on
the board.

- The tools on a sheet: tips, lines cut at the edge, rectangles of each
  style, and every ellipse from 1 by 1 to 40 by 30 at four thicknesses
  (closed, inside its box, touching all four sides, the same mirrored).
  The fill through a spiral of walls with room for 4,096 places, for 3 and
  for 1: the same result.
- The window, with the mouse and the keys: each tool, the sizes and
  styles, ink and paper, Undo and back, a line that follows the pointer
  and leaves nothing behind, drawing past the edge, the Image menu; after
  each, what the screen shows is the sheet, and a full repaint changes
  nothing.
- Files: Save asks for a name once; the file decodes to exactly the sheet
  with no dithering, with Floyd-Steinberg and with the 4x4 pattern; a
  sheet 333 dots wide (rows filled up to 336 bytes) too; New; Open;
  closing with changes asks; started with a file; a file that is no
  picture says so.
- Memory: an open Pincel has its two copies of the sheet out and little
  else (under 8 KB more); closed, everything is back. Two at once.
- The window in the four themes (the reference pictures).
- The other reference pictures changed where they should: the Start
  menu's list of programs has one more line, and the drive's free space in
  the File manager's status line is less by the program's file.

## What was learned

- A picture that is not made with `kOnce` must still paint every pixel of
  itself: the gaps between the palette's colours showed as dark dots after
  the palette alone was painted again, and the test for stale pixels
  caught it.
- With "a pixel is inside when its middle is", a flat ellipse (36 by 2)
  came out 4 dots shorter than its box. The middle row, or the middle two,
  now take the whole width.
- `wm::key::letter` is not among the names a program file may ask for;
  the keys are read by their codes, as Chess does.
- In the cloud container the PC test `doom` fails with or without this
  change: its program file is 1.7 MB in the checked build there, over the
  1 MB the test allows.

## What is left

- The board: that it starts from the Start menu, that pulling a shape and
  the brush keep up with the mouse, how long a sheet of 800 by 600 takes
  to save and a JPEG to open, and no missed refills meanwhile.
- The owner's word on the design (the decision is to confirm).
- Not in this version: zoom, a selection with Cut, Copy and Paste, text,
  the right button drawing with the paper colour (it needs the system to
  give programs the right button's drag), and a way to open a picture in
  Pincel from the File manager (a double click opens the Picture viewer).
- The Linux program and the web page get Pincel from the same folder;
  neither was built here (no SDL2, no Emscripten in the cloud).
